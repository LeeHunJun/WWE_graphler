# 비동기 AI 분석 API

앞단 웹 프록시가 한 HTTP 요청을 60초에 종료할 수 있어, 문서 분석 요청을 연결을 오래 유지하지 않는 작업 방식으로 처리합니다.

## 분석 시작

`POST /api/ai-summarize`에 `{ "document": { "name", "type", "sources" } }`를 보냅니다. 접수되면 오래 기다리지 않고 `202 Accepted`와 작업 ID를 반환합니다.

```json
{ "jobId": "<uuid>", "status": "processing", "pollAfterMs": 750 }
```

## 진행 상태 확인

`GET /api/ai-summarize/:jobId`를 `pollAfterMs` 간격으로 다시 요청합니다. 작업 중이면 `202`와 `queued` 또는 `processing`을, 끝나면 완료된 요약을 `200`으로 반환합니다. 실패하면 적절한 오류 상태와 안전한 오류 메시지를 반환합니다.

프로젝트 화면은 이 두 단계를 자동으로 처리합니다. 작업 ID는 무작위 UUID이고, 완료 결과는 10분 뒤 메모리에서 만료됩니다. 서버 재시작 시 진행 중 작업은 이어지지 않으므로 다시 분석해야 합니다.

## 처리 한도

- 문서 구간은 최대 3개씩 처리하고, 문서 하나의 분석은 최대 5분입니다.
- 동시에 분석하는 문서는 1개, 대기열은 최대 1개입니다. 대기열이 꽉 차면 `429 AI_QUEUE_FULL`이 반환되므로 잠시 후 재시도해야 합니다.
- 긴 문서 구간은 검증 실패 시 한 번, 한 구간짜리 짧은 문서는 두 번까지 재시도합니다. 모델 호출별 제한은 35초입니다.
- 진단 기록에는 작업 ID, 구간 번호, 시도 번호, 단계별 소요 시간이 저장되고 API 키는 기록하지 않습니다.
